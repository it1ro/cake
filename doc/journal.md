## 2026-09-20 — Процессор Go, дерево, тесты

### Что сделано
- `internal/processor` — интерфейс `Processor`, реестр, `Language()`,
  фолбэк `passthrough`.
- `internal/processor/golang` — strip комментариев через `go/printer`,
  сохранение build-констрейнтов и `//go:*` директив, флаг `KeepDoc`.
- `walker.Tree` — ASCII-дерево с `├──` / `└──`, совместимое с `tree(1)`.
- `cmd.clean` — новая команда CLI.
- `pipeline` — режим `ModeDump` / `ModeClean`, прогон через процессор.
- `render/xml` — переключён на `walker.Tree`, эскейпинг `]]>`.
- Тесты: `golang_test.go`, `walker_test.go`, `xml_test.go`.
- Makefile с типовыми целями (build/test/lint/cover/release-snapshot).
- `cmd/cake/main.go` — ldflags-переменные версии.

### Решения
- **`processor.Language` — единая точка правды.** Дублирование с
  `walker` убрано; walker теперь импортирует processor (циклов нет,
  потому что processor не зависит от walker).
- **Регистрация процессоров через `init()` + blank import.** В
  `main.go` явный `_ ".../processor/golang"` — линтер не удалит,
  реестр заполнен к моменту `Execute()`.
- **`f.Comments` не оставляем `nil`.** Если `nil`, `go/printer`
  переключается в `useNodeComments` и печатает комментарии из
  `.Doc`-полей AST, обходя фильтр. Заводим пустой срез явно.
- **Malformed-файл → исходник без ошибки.** Пайплайн не должен
  падать из-за одного битого файла (например, под чужой GOOS).
- **Тесты — `wantContains` / `wantNotContains`, а не golden.**
  `go/printer` может сдвинуть пустые строки; golden-файл будет
  ложно падать на незначительных изменениях формата.
- **Tabwidth=8 в printer.** Как в `gofmt`; отступы всё равно табами
  (`printer.TabIndent`), значение влияет только на выравнивание.

### Открытые вопросы
- Как быть с файлами под чужой `//go:build`? Сейчас — «включать
  всё, помечать в метаданных». Возможно, стоит уважать
  `runtime.GOOS/GOARCH` флагом.
- `//line` директивы: сохраняем, но не факт что нужно — они ломают
  нумерацию строк в выводе. Понаблюдать.
- Оценка токенов — по-прежнему нули в `<context tokens="0">`.
  Ждёт v0.2.

2. `cmd/pick` — TUI на bubbletea.

## 2026-09-20 — Старт проекта

### Что сделано
- Определены три use case MVP: dump, clean, pick.
- Зафиксирована архитектура (см. architecture.md).
- Выбран стек без CGo.

### Решения
- **Один pipeline, три команды.** Не дублировать логику в TUI и CLI.
- **Без tree-sitter на старте.** `go/ast` даёт 100% точность для Go.
- **XML как формат по умолчанию.** LLM стабильно его парсят; теги
  чётко разделяют метаданные и содержимое.
- **OSC 52 в приоритете над cgo-буфером.** Не ломает статическую сборку.

### Открытые вопросы
- Оценка токенов: эвристика `/4` или сразу tiktoken? Решение: эвристика
  в v0.1, tiktoken — опция во v0.2.
- Как обрабатывать файлы с build-тегами? Пока — включать всё, помечать
  в метаданных.
- Формат дерева: свой или через готовую либу? Свой — проще контролировать
  префиксы `├──`/`└──`.

### Следующие шаги
1. `go mod init`.
2. Скелет `cmd/cake` + cobra root.
3. `internal/walker` с базовым обходом (без gitignore).
4. Ручной smoke-тест на этом репо.

### Правки после первого прогона тестов
- **Квотирование атрибутов в XML.** `files=%d` и `lines=%d` печатались
  без кавычек — невалидный XML. Пофикшено на `files="%d"`. Тест
  `TestXML_Basic` поймал это сразу, что подтверждает ценность
  golden-ожиданий для формата вывода.

## 2026-09-20 — .gitignore

### Что сделано
- `internal/gitignore` — собственный парсер .gitignore.
- Поддержка вложенных .gitignore (стек правил).
- `!`-инвертирование, `dir/`, якорные паттерны, `**`.
- Флаг `--no-gitignore` в `dump` и `clean` (по умолчанию — включено).
- Интеграция в `walker.Walk` через `Options.UseGitignore`.
- Тесты: 8 кейсов на matcher, интеграционный тест на walker.

### Решения
- **Не используем `sabhiram/go-gitignore`.** Не поддерживает
  вложенные `.gitignore` и dir-only правила. Свой парсер — 250 строк,
  ноль зависимостей, точно под наш кейс.
- **Не используем regexp.** Для дерева из 50k путей и сотен правил
  ручной матчер быстрее и без аллокаций на компиляцию.
- **Не поддерживаем `[...]`.** Редко встречается в .gitignore,
  добавлять сейчас — преждевременно.
- **Загрузка .gitignore до проверки самой директории.** Соответствует
  семантике git.

### Открытые вопросы
- `matchHere` для `**` — черновая реализация. Если тесты не покроют
  все случаи, переписать на канонический матчер с мемоизацией (i, j).
- Читать ли `.git/info/exclude`? Пока нет.
- Поведение с симлинками на директории — сейчас WalkDir не заходит,
  значит и .gitignore там не читается. Ок.

### Замечания ревью
- `internal/gitignore/gitignore.go` изначально был пустым — добавлен код.
- `internal/walker/walker.go` был обрезан — восстановлены `Tree`,
  `matches`, `isBinary`, импорт `doublestar`.
- Порядок `.gitignore`-логики поправлен: сначала проверяем директорию
  по родительским правилам, потом читаем её собственный `.gitignore`.
- `main.go` теперь вызывает `cli.SetVersion()`.
- Package-комментарии перенесены перед `package` (ST1000).
- `matchPattern` переписан с мемоизацией — экспоненциальный
  worst case `**` устранён.
