# cake

CLI для извлечения контекста из кодовой базы в форматы, удобные
для LLM (Claude, GPT, локальные модели). Go-центричный, с заделом
под другие языки.

Один бинарь. Без CGo. Работает из коробки в любом репозитории.

## Зачем

Передать проект в чат LLM — больно. Копируешь файлы вручную,
забываешь про `.gitignore`, комментарии занимают половину
контекста, а общий размер не влезает ни в одно окно.

`cake` делает три вещи:

- **dump** — обход проекта, дерево, каждый файл в теге.
- **clean** — то же, но Go-код без комментариев.
- **pick** — интерактивный выбор файлов в TUI.

## Установка

### Go

```bash
go install github.com/it1ro/cake/cmd/cake@latest
```

### Бинарь с GitHub Releases

Скачай из [releases](https://github.com/it1ro/cake/releases) под
свою платформу: `linux/amd64`, `linux/arm64`, `darwin/amd64`,
`darwin/arm64`, `windows/amd64`.

## Быстрый старт

```bash
# Интерактивный выбор файлов — TUI сразу в дереве
cake

# Весь проект (кроме .gitignore) → буфер обмена
cake .

# Дамп в stdout
cake dump .

# Go без комментариев
cake clean .
```

`cake .` удобно для «взял и вставил»: в stdout ничего не пишется,
содержимое уходит в буфер обмена по OSC 52, а в stderr печатается
краткий отчёт:

```
✓ copied 24924 files · ~47M tok · 194.0 MB → clipboard
```

## Команды

| Команда | Что делает | Когда использовать |
|---|---|---|
| `cake [path]` | Без аргументов — TUI. С путём — dump + clipboard. | Быстрые сценарии. |
| `dump [path]` | Полный тегированный дамп. Содержимое как есть. | Нужны README, конфиги, комментарии. |
| `clean [path]` | Go-код без комментариев. Не-Go — как есть. | Нужна только логика, экономия токенов. |
| `pick [path]` | Интерактивный выбор в TUI. | Точечный набор файлов. |

## Флаги

Общие для `dump`, `clean`, `pick`:

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `-i, --include` | все | glob-паттерны включения (`**/*.go`, можно повторять) |
| `-e, --exclude` | — | glob-паттерны исключения |
| `--max-size` | `1<<20` (1 МБ) | пропускать файлы больше N байт; 0 = без лимита |
| `-o, --output` | stdout | писать в файл |
| `--format` | `xml` | `xml` \| `markdown` \| `plain` |
| `--budget` | 0 | лимит токенов; файлы сверх — пропускаются |
| `--clipboard` | false | копировать в буфер (вместо stdout) |
| `--no-gitignore` | false | не учитывать `.gitignore` |
| `--context-limit` | из `cake.toml`, иначе нет | лимит контекста модели |
| `--reserve` | `clamp(limit/10, 1000, 20000)` | резерв под system prompt и ответ |
| `--on-overflow` | `fail` | `fail` \| `drop` |
| `--profile` | `default` | профиль из `cake.toml` |
| `--report-file` | — | путь к JSON-отчёту о переполнении |
| `-v, --verbose` | false | печатать путь применённого `cake.toml` |

**Только `clean`:**

| Флаг | Что делает |
|---|---|
| `--keep-doc` | сохранять doc-комментарии (build-теги и `//go:*` остаются всегда) |

## Лимит контекста

`--context-limit` задаёт окно модели, `--reserve` — запас на system
prompt и ответ. Если оценка превышает `limit − reserve`, `cake`
печатает отчёт в stderr и завершается с кодом `3`
(`--on-overflow=fail`, по умолчанию). Режим `drop` обрезает набор
до потолка и возвращает `0`. `--budget` остаётся жёстким фильтром
и комбинируется с лимитом: эффективный потолок =
`min(budget, limit − reserve)`.

### Таблица состояний

| `limit` | `budget` | `on-overflow` | Результат |
|---|---|---|---|
| нет | нет | — | как раньше, проверок нет |
| нет | N | — | жёсткая обрезка, `dropped="N"` |
| L | нет | `fail` | если > `L−reserve`: отчёт в stderr, exit 3, вывода нет |
| L | нет | `drop` | обрезка до `L−reserve`, exit 0 |
| L | N | `fail` | `budget` режет; если всё ещё > `L−reserve`: exit 3 |
| L | N | `drop` | потолок `min(N, L−reserve)`; предупреждение, если `N` больше |

Коды выхода:

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | ошибка (не смогли прочитать файл и т.п.) |
| `3` | переполнение контекста (при `--on-overflow=fail`) |

### `cake.toml`

Файл в корне проекта (или вверх до `.git`). Глобальный —
`$XDG_CONFIG_HOME/cake/config.toml` или `os.UserConfigDir()/cake/config.toml`.

```toml
version = 1

[default]
context-limit = "200k"
on-overflow   = "fail"
format        = "xml"
exclude       = ["**/*_test.go"]

[profiles.local]
context-limit = "32k"
format        = "markdown"

[profiles.ci]
on-overflow   = "drop"
```

Приоритет слияния: флаг (`Changed`) > профиль > `[default]` (локальный) >
глобальный `[default]` > встроенные дефолты. Списки `include`/`exclude`
дополняются; `--exclude ''` — явный сброс. `reserve` можно задать числом
(`"20000"`) или процентом (`"10%"`). Если профиль переопределяет
`context-limit` и не задаёт `reserve`, резерв считается заново от нового
лимита.

`--context-limit 0` отключает лимит из конфига на один запуск.

### Пример отчёта

```text
✗ не влезаем: ≈247k tok при потолке 180k (лимит 200k, резерв 20k)  [оценка по Size]

Где вес:
  internal/    118k  48%   (312 файлов)
  doc/          61k  25%
  ./            12k   5%    (README.md, go.mod, ...)

Расширения:  .go 141k · .md 70k · .json 21k

Что сделать (набор влезает):
  -e 'doc/**' -e '**/*_test.go'          → ≈171k  ✓
  cake pick .                            → вручную
```

Мера `--mode clean` в отчёте появится в v0.3. Отброшенные файлы
остаются в `<tree>` схлопнутыми директориями (`<omitted>` в XML,
секция в markdown, `omitted:` в plain) — модель видит, что код был,
и может запросить его отдельно.

## Примеры

```bash
# Только Go и markdown, обрезать по 50k токенов
cake dump . -i "**/*.go" -i "**/*.md" --budget 50000 -o ctx.xml

# Чистый Go-код в markdown, в буфер
cake clean . -i "**/*.go" --format markdown --clipboard

# Исключить тесты и вендор
cake dump . -e "**/*_test.go" -e "vendor/**"

# Посмотреть, что скрыто .gitignore
cake dump . --no-gitignore -o full.xml

# Под лимит Claude 200k
cake dump . --context-limit 200k -o ctx.xml

# Профиль из cake.toml
cake dump . --profile cheap -o ctx.xml
```

`--budget` работает как фильтр: файлы, не влезающие в лимит,
пропускаются, порядок оставшихся сохраняется. В выводе появляется
`dropped="N"` — видно, сколько отброшено.

Типичные числа для крупного проекта: kubernetes/kubernetes даёт
24 924 файла и ~47M токенов. Без `--budget` такой дамп не влезет
ни в один контекст — либо фильтруйте `-i`, либо режьте бюджетом.

## TUI (pick)

<!-- screenshot: TUI pick в tree-режиме, список файлов и дерево -->

```
cake pick [path]
```

Открывается список файлов проекта, стартует в древовидном режиме.
Слева — маркер `[ ] / [x] / [-]`, директории с `▾/▸`, в футере —
счётчик выбранных и live-оценка токенов.

При заданном `--context-limit` в статусной строке появляется
индикатор: `≈180k / 180k`, жёлтый от 90%, красный выше 100%.
В clean-режиме рядом с числом стоит `≤` — оценка сверху, точное
значение после процессоров. `enter` не блокируется: пользователь
сам решает, экспортировать или нет.

Композиция центрируется на широких экранах (макс. ширина 110
колонок, настраивается через `CAKE_WIDTH`): длинные пути легче
читать, когда строка не расползается на весь монитор.

**Клавиши:**

| Клавиша | Действие |
|---|---|
| `↑` `↓` / `j` `k` | перемещение |
| `g` / `G` | в начало / в конец |
| `space` | выбрать/снять (на директории — всё поддерево) |
| `a` / `A` | выбрать / снять всё |
| `d` | toggle директории под курсором |
| `←` `→` / `h` `l` | свернуть / развернуть (tree) |
| `t` | переключить tree ↔ flat |
| `/` | фильтр (fuzzy в flat, подстрочный в tree); `esc` — сбросить |
| `tab` | переключить режим dump ↔ clean |
| `f` | переключить формат xml → markdown → plain |
| `⏎` | экспорт и выход |
| `q` / `ctrl+c` | выход без вывода |

`esc` во время фильтра сбрасывает его; вне фильтра — ничего не делает.

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `CAKE_WIDTH` | `110` | Макс. ширина контентной области в TUI. На широких экранах композиция центрируется в этом пределе. Значения `< 40` игнорируются. |
| `CAKE_ICONS` | не задано | Если непустое — включает иконки Nerd Font рядом с именами файлов и директорий. Требует установленного шрифта, иначе будут «квадратики». |
| `NO_COLOR` | не задано | Отключает ANSI-цвета в summary после `--clipboard` (стандартное поведение). |
| `XDG_CONFIG_HOME` | системный | Где искать глобальный `cake/config.toml`. |

```bash
# Шире, чем по умолчанию — если пути длинные и монитор большой
CAKE_WIDTH=160 cake pick .

# Иконки Nerd Font в дереве
CAKE_ICONS=1 cake pick .
```

## Форматы вывода

### xml (по умолчанию)

```xml
<context project="." files="42" tokens="18432">
  <tree><![CDATA[
  ├── cmd/
  │   └── main.go
  └── internal/walker/walker.go
  ]]></tree>

  <file path="cmd/main.go" lang="go" lines="24" bytes="512">
  <![CDATA[
package main
...
  ]]>
  </file>
</context>
```

Содержимое в `<![CDATA[…]]>`, последовательность `]]>` внутри
кода экранируется через два CDATA-блока: `]]]]><![CDATA[>`.
LLM стабильно парсят XML: теги чётко разделяют метаданные и код.

При `--budget` или `--context-limit=drop` в `<context>` добавляется
`dropped="N"`, а рядом с `<tree>` — `<omitted count="N">` со
схлопнутыми директориями отброшенного.

### markdown

````markdown
# Context: .

_Files: 42 · Tokens: ~18432_

## Tree

```
├── cmd/
│   └── main.go
```

## `cmd/main.go`

_go · 24 lines · 512 bytes_

```go
package main
```
````

Удобно вставлять прямо в чат: заголовки сворачиваются в TOC,
code-блоки подсвечиваются. Внутренние тройные backticks
экранируются через outer fence с четырьмя backticks (обёртка `````),
чтобы не рвать внутренний fence.

### plain

```
project: .
files: 42, tokens: ~18432

tree:
├── cmd/
│   └── main.go

────── cmd/main.go (go) ──────
package main
```

Для отладки и диффов.

## Буфер обмена (OSC 52)

`--clipboard` копирует через OSC 52 — escape-последовательность,
которую понимают:

- iTerm2, kitty, WezTerm, alacritty, Windows Terminal, Warp
- tmux: требует `set -g set-clipboard on` в `~/.tmux.conf`

С `--clipboard` вывод не идёт в stdout: содержимое уходит в буфер,
а в stderr печатается однострочный отчёт. Если задан `--output`,
файл тоже пишется — оба назначения независимы.

**Чего OSC 52 не умеет.** Некоторые терминалы и промежуточные
хопы (SSH через несколько хостов, screen без патчей) молча
игнорируют последовательность. `cake` не узнаёт об этом — отчёт
`✓ copied` в stderr означает «записали в tty», а не «терминал
скопировал». Если вставка не работает — проверь терминал.

**Лимит.** xterm режет последовательность на 100 KB, некоторые —
на 8 MB. На больших проектах содержимое может обрезаться. Если
`cake` видит, что вывод больше 100 KB, в summary добавляется
предупреждение с подсказкой `-o file`.

## Как это работает

- **Обход.** `filepath.WalkDir` + стек `.gitignore` (корневой
  и вложенные), правила `!`, `dir/`, `**`, якорные паттерны.
  `.git/`, `node_modules/`, `vendor/` — всегда исключены.
- **Язык.** Определяется по расширению через единый реестр
  процессоров.
- **Clean.** Для `.go` — `go/parser` + `go/printer`: удаляются
  обычные и doc-комментарии, сохраняются `//go:build`,
  `// +build`, `//go:generate`, `//go:embed`, `//line`.
  Не-Go файлы проходят без изменений.
- **Токены.** Эвристика `len/4` с округлением вверх. Ошибка
  в пределах 10–15% для кода и латиницы; для CJK занижает.
  Считается содержимое файлов **плюс обвязка формата**:
  XML-теги, CDATA-маркеры, строки дерева, markdown-заголовки.
  Обвязка оценивается прогоном настоящего рендера с пустым
  содержимым, поэтому правка шаблона автоматически попадает
  в оценку. Направление ошибки безопасное: `--budget`,
  поставленный «по цифре», обрежет чуть консервативнее.
- **Стриминг.** XML и markdown пишутся по одному файлу через
  `bufio.Writer`; весь вывод в память не буферизуется, кроме
  случая `--clipboard`, где нужен полный base64-payload.

## Прогресс на больших проектах

При чтении больше 200 файлов cake рисует однострочный индикатор
в stderr:

    847/24924 файлов (3%)

В TTY — включён, в пайпе молчит (не засоряет CI-логи).
Отключается `--no-progress`.

## Без CGo

Ни одной C-зависимости. Что это даёт:

- **Статические бинари.** `GOOS=linux GOARCH=amd64 go build` —
  и бинарь работает на любой Linux-машине без glibc-плясок.
- **Кросс-компиляция из коробки.** Никаких `CGO_ENABLED=0`-хаков
  или кросс-toolchain'ов.
- **Простая сборка.** `go build` — и всё. Не нужен gcc, clang,
  LLVM, tree-sitter-биндинги.

Клипборд через OSC 52, а не через системный API — тоже ради
этого. OSC 52 не требует cgo, работает поверх терминала.

## Разработка

```bash
make help             # список целей
make build            # ./bin/cake под текущую платформу
make build-all        # кросс-сборка под 5 платформ
make build-matrix     # проверка компиляции без записи бинарей
make test             # go test ./...
make test-race        # с race-детектором
make smoke            # контракт exit-кодов, fail/drop, cake.toml
make cover            # HTML-отчёт в coverage.html
make check            # fmt-check + vet
make ci               # check + test-race + build-matrix + smoke
make release-snapshot # локальный goreleaser
make bench-k8s        # замер на kubernetes/kubernetes (opt-in)
```

Требуется Go 1.22+, GNU make, `golangci-lint` и `goreleaser` для
`make lint` и `make release-snapshot` (см. `make tools`).

### Smoke-тест

`scripts/smoke.sh` — end-to-end проверка CLI-контракта: строит
песочницу в `mktemp`, прогоняет `cake dump` в семи сценариях
(всё влезает / fail / drop / `--report-file` / несуществующая
директория / `-v` / профили / `--context-limit 0`) и сверяет
exit-коды, содержимое XML и stderr. Не заменяет `go test` —
проверяет то, что в unit-тестах неудобно: реальные коды выхода
процесса и файлы на диске.

```bash
make smoke
# или напрямую
./scripts/smoke.sh
```
